# Acceptance Protocol

## 通用验收表

| 检查项 | 必需 | 结果 | 证据 |
|---|---:|---|---|
| 目标文件/配置结构有效 | 是 | ☐ 通过 ☐ 失败 ☐ 未执行 | |
| 新会话可以创建 | Safety 必需 | ☐ 通过 ☐ 失败 ☐ 未执行 | |
| 没有重复安装宿主核心包 | Safety 必需 | ☐ 通过 ☐ 失败 ☐ 未执行 | |
| 预期命令/工具可见 | 视变更 | ☐ 通过 ☐ 失败 ☐ 未执行 | |
| 普通任务不误触发 | 视 skill 变更 | ☐ 通过 ☐ 失败 ☐ 未执行 | |
| 回滚命令已验证 | Safety 必需 | ☐ 通过 ☐ 失败 ☐ 未执行 | |

## 状态规则

- `done` 只能在所有必需项为“通过”时使用。
- `失败` 必须记录原因、影响和下一步；不能用用户口头确认覆盖。
- `未执行` 必须说明为什么未执行以及谁批准了例外。

## DSH 插件安装验收示例

1. 核对发布包完整性（如有 SHA256SUMS）。
2. 检查目标包没有把宿主核心 `@deepseek-ai/*` 装进 profile `node_modules`。
3. 检查新增 patch 使用 `insert` 语义。
4. 重启后创建新会话。
5. 检查预期命令或工具出现。
6. 执行一次非目标任务，确认不误触发。
7. 确认回滚命令和备份路径。
